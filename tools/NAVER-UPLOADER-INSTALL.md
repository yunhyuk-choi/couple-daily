# 네이버 사진 업로더 — 설치 (데스크톱 · Android · iPhone)

후기 사진을 네이버 블로그에 **정식(내부) 이미지**로 올리고 본문까지 조립해 주는
스크립트다. 앱의 후기 화면에서 **📤 네이버로 보내기**로 페이로드를 복사한 뒤,
오버레이 칸에 붙여넣고 **🅢 정식 삽입** 을 누르면 된다.

**형태는 둘인데 소스는 하나다:**

| 형태 | 쓰는 환경 | 파일 | 뜨는 방식 |
|---|---|---|---|
| **북마클릿** | **데스크톱** (Chrome · Edge · Firefox) | `tools/naver-uploader.bookmarklet.txt` | 글쓰기 페이지에서 **즐겨찾기 클릭** |
| **유저스크립트** | Android · iPhone (확장 지원 브라우저) | `tools/naver-uploader.user.js` | 글쓰기 페이지를 열면 **자동** |

북마클릿은 유저스크립트의 **사본이 아니라 거기서 생성된 것**이다
(`python tools/build_bookmarklet.py`). 기능 — 사진 크롭 · URL 페이로드 · 강조 서식
(**굵게** · ==형광펜== · *분홍* · `파랑`) · v2 자동 삽입 — 은 **정의상 같고**, 둘이
어긋나면 `tests/test_bookmarklet_build.py` 와 `--check` 가 막는다. 예전처럼 "로직은
동일하다"는 *약속*으로 두 사본을 유지하지 않는다.

> ⚠️ **옛 북마클릿을 즐겨찾기에 넣어 뒀다면 지금 새 것으로 덮어써라.**
> 2026-10-13 에 옛 북마클릿 파일을 지웠지만 **브라우저 즐겨찾기에 설치된 것은 파일을
> 지워도 그대로 남아 있다.** 옛 것은 앱이 보내는 새 페이로드(사진 **URL + 크롭 좌표**)를
> 받을 코드가 없어 **사진이 조용히 비어 나간다**(아래 「왜 URL 인가」). 즐겨찾기 항목을
> 편집해 **URL 칸의 내용을 통째로 새 `.txt` 내용으로 갈아끼우면** 된다 — 아래 1~3.

## 데스크톱 (Chrome · Edge · Firefox) — 북마클릿

유저스크립트 매니저를 깔지 않는다. 즐겨찾기 하나면 된다.

1. 리포의 **`tools/naver-uploader.bookmarklet.txt`** 를 열어 **내용 전체**를 복사한다
   (한 줄 · 약 95KB — 에디터에서 `Ctrl+A` → `Ctrl+C`). 일부만 복사하면 조용히 깨진다.
   - 원본(raw) URL:
     `https://raw.githubusercontent.com/yunhyuk-choi/couple-daily/main/tools/naver-uploader.bookmarklet.txt`
2. 브라우저 **즐겨찾기 관리자**를 연다 (Chrome · Edge · Firefox 모두 `Ctrl+Shift+O`).
3. 새 즐겨찾기를 추가한다 — **이름**은 아무거나(`네이버 업로더`), **URL 칸**에 복사한
   내용을 붙여넣는다.
   - ⚠️ **주소창에 붙여넣으면 안 된다.** 크롬·엣지는 주소창에 붙은 `javascript:` 접두를
     **말없이 지운다** — 그러면 그냥 검색어가 되고 "북마클릿이 안 된다"로 보인다.
   - 옛 북마클릿이 이미 있으면 **그 항목을 편집**해서 URL 칸만 갈아끼운다(위 ⚠️).
4. 네이버 블로그 **글쓰기** 페이지를 연 뒤 그 즐겨찾기를 **클릭**한다 → 오버레이가 뜬다.
   모바일과 달리 자동으로 뜨지 않는다 — 데스크톱은 **클릭이 방아쇠**다.
5. 이후는 아래 「자동(v2)」 · 「수동(v1) 폴백」과 **똑같다.**

- 오버레이 제목 오른쪽의 **`v…`** 가 지금 설치된 버전이다. 리포 `.user.js` 의
  `@version` 과 다르면 즐겨찾기가 낡은 것이니 1~3 을 다시 한다.
  ⭐ **이제 앱이 먼저 말해 준다** — 스크립트가 대기 조회(`?v=`)에 자기 버전을 실어
  보내고, 앱이 기대값과 다르면 ① 오버레이 맨 위에 노란 경고줄을 띄우고 ② **앱 화면**
  (설정 · 후기 상세의 📤 옆)에도 같은 문장을 적는다. ②가 따로 있는 이유: 버전을 보낼
  줄 모르는 **옛 사본**은 ①을 띄울 줄도 모르기 때문이다. 버전을 안 보내면 앱은
  "어떤 사본인지 모르겠다 — 다시 등록해라"로 안내하고, **하던 일(페이로드 전달)은
  그대로 한다.**
- 유저스크립트도 같이 설치돼 있으면 중복 주입 가드(`__cdUserscriptRan`)가 걸려
  북마클릿 클릭이 **아무 일도 하지 않는다.** 정상이다 — 이미 오버레이가 떠 있다.

## Android (Firefox 또는 Kiwi Browser)

- 원본(raw) URL:
  `https://raw.githubusercontent.com/yunhyuk-choi/couple-daily/main/tools/naver-uploader.user.js`

1. **Firefox** 또는 **Kiwi Browser** 를 설치한다(둘 다 확장 지원).
2. 브라우저 확장 스토어에서 **Tampermonkey** 를 설치한다.
   - Firefox: `about:addons` → 부가 기능 검색 → Tampermonkey 추가.
   - Kiwi: 메뉴 → Extensions → Chrome 웹스토어에서 Tampermonkey 설치.
3. 위 **raw `.user.js` URL** 을 주소창에 열면 Tampermonkey 가 **설치 창**을 띄운다 → *설치*.
4. 네이버 블로그 **글쓰기** 페이지를 연다 → 오버레이가 자동으로 나타난다.

## iPhone (Safari + "Userscripts")

1. App Store 에서 **Userscripts**(무료) 를 설치한다.
2. **설정 → Safari → 확장 프로그램** 에서 **Userscripts** 를 켜고,
   `blog.naver.com`(및 `m.blog.naver.com`) 접근을 **허용** 한다.
3. Userscripts 앱을 열어 관리자로 들어가 **새 스크립트 추가** →
   위 `.user.js` 내용을 **붙여넣기**(또는 파일로 불러오기) 후 저장한다.
   - 파일이 필요하면 raw URL 을 사파리로 열어 내용을 복사한다.
4. Safari 에서 네이버 블로그 **글쓰기** 페이지를 연다 → 오버레이가 자동으로 나타난다.

## 자동(v2) — 붙여넣기·버튼 없이

1. **최초 1회**: 앱 **설정** 화면의 "네이버 업로더 키"를 복사 → 네이버 글쓰기 페이지에서
   유저스크립트 오버레이의 **내보내기 키 입력** 칸에 붙여넣고 저장(브라우저 localStorage에
   `cd_export_key`로 저장돼 이후 생략).
2. 앱 후기 상세에서 **📤 네이버로 보내기** 를 누른다(서버에 "이 후기 대기" 표시 +
   클립보드 복사 폴백).
3. 네이버 글쓰기 페이지를 **열거나 새로고침** 한다 → 유저스크립트가 대기 후기를 가져와
   사진 업로드·본문 조립까지 **자동**으로 넣는다. 확인 후 발행.

## 수동(v1) 폴백 — 붙여넣기

1. 앱의 후기 상세에서 **📤 네이버로 보내기** → 페이로드(JSON)가 클립보드에 복사됨.
2. 네이버 글쓰기 화면의 오버레이 칸에 **붙여넣기**(Ctrl+V / 길게 눌러 붙여넣기).
3. **🅢 정식 삽입 (setDocumentData)** 을 누른다 → 사진이 네이버 인프라로 업로드되고
   제목·본문·별점·해시태그까지 조립되어 편집기에 들어간다. 확인 후 발행.
4. 자동/삽입이 안 되면 **처리 ▶** / **🅳 데이터URI** / **🔬 에디터 API 탐색** 과
   **🔍 진단 로그** 로 원인을 확인한다(토큰이 안 잡히면 오버레이의 **🔑 토큰 수동입력**).

## 왜 URL 인가 — 클립보드는 사진을 못 나른다

앱의 **📤 네이버로 보내기**는 사진 바이트를 클립보드에 담지 **않는다.** 담았더니
아이폰·안드로이드 양쪽에서 실패했다(2026-10-13 실측):

| 담는 것 | 사진 1장 | 8장 |
|---|---|---|
| 예전 — base64 data URI | 2.8~3.9MB | **22~31MB** |
| 지금 — 서명 URL + 크롭 좌표 | — | **수십 KB** |

- **안드로이드**: 클립보드가 바인더 IPC 를 타서 트랜잭션 상한이 ~1MB 다. **한 장만
  으로도** 넘는다.
- **iOS 사파리**: 사진을 받아 캔버스로 굽는 동안 사용자 제스처(transient activation)가
  풀려, 그 뒤의 클립보드 쓰기가 **크기와 무관하게** 거절된다.

그래서 클립보드에는 **공개 서명 URL 과 크롭 좌표만** 들어가고, 실제 바이트는 이
유저스크립트가 그 URL 에서 받아 Canvas 로 자른 뒤 **네이버에 업로드**한다.
발행된 글의 사진은 그대로 **네이버 내부 이미지**다 — 외부 링크로 올려 글이
삭제되던 문제는 재발하지 않는다(그 결론은 *최종 글* 에 대한 것이고, 클립보드가
바이트를 날라야 한다는 뜻이 아니었다).

## 메모

- 스크립트는 **최상위 프레임에서만** 오버레이를 띄우고(중복 방지), 에디터 iframe 은
  same-origin 프레임-워크로 커버한다.
- 글쓰기 페이지가 아니면 잠잠(dormant)하다 — 다른 네이버 페이지에선 아무것도 안 뜬다.
- `@grant none` 이라 페이지 컨텍스트에서 동작하며, 격리 엔진 대비로 `unsafeWindow` 를
  우선 사용해 `SmartEditor`·fetch/XHR 후킹이 실제 페이지 window 에서 이뤄지게 한다.
- 업데이트: 리포의 `.user.js` 가 바뀌면 Tampermonkey 는 raw URL 로 갱신 확인, iPhone
  Userscripts 는 내용을 다시 붙여넣으면 된다. **데스크톱 북마클릿은 자동 갱신이 없다** —
  위 「데스크톱」 1~3 을 다시 해서 URL 칸을 갈아끼운다.
- 고치는 곳은 **`.user.js` 하나뿐**이다. 고친 뒤 버전을 올리고(메타의 `@version` **한
  줄**이 단일 원천 — 본문 `var VERSION` 리터럴은 빌더가 심는다) 아래를 돌려 북마클릿을
  다시 만든 다음 **둘 다 커밋**한다:

  ```
  python tools/build_bookmarklet.py          # 다시 생성
  python tools/build_bookmarklet.py --check  # 생성물이 원천과 일치하나 (CI/로컬 점검)
  ```
